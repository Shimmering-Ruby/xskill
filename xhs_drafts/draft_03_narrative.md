# 方案三：人味叙事型 -- "像朋友在聊天"

## 策略说明

以第一人称讲述一个真实场景：团队里每个人都在重复教 agent 做同样的事，作者从烦躁到寻找解决方案到最终落地 xskill 的心路历程。关键是制造"我也遇到过这个问题"的共鸣感。语气像一个技术群里聊天时有人突然分享了个好东西，而不是产品发布会。低 AI 味 + 真实吐槽 = 高互动意愿。

## 封面图描述

**风格**：浅色、干净、手绘感。模拟 iMessage/微信聊天界面风格。

**主体**：一个模拟的聊天窗口截图，对话如下：
- 灰色气泡（同事）："你之前配 nginx 反代怎么搞定的？Claude Code 又在瞎建议"
- 蓝色气泡（我）："等下我发你我的 CLAUDE.md 里那段"
- 灰色气泡："算了我问了三个人了每个人写法都不一样"
- 蓝色气泡："..."

**底部**：一行手写体文字 "这件事重复了第 47 次之后我终于受不了了"

**配色**：白色背景，iOS 风格气泡，底部文字用深灰手写体。整体简洁、生活化、不像技术文章。

## 标题

第 47 次教 agent 配环境后我崩溃了

## 正文

哎我上周四又教 Claude Code 配 Nginx 反向代理，第 47 次了吧？实际可能没那么多，但感觉上就是第 47 次。我们团队一共 6 个人，全在用 coding agent，每个人都在单刷自己那份技能点。结果呢？小张群里问 proxy_pass 怎么写，我发我的写法，小李说他那样也行，小王直接甩个模板——三种写法都能用，但没一个完整的。大家各自闷头研究同一个破问题，重复造轮子。

我算了一笔账，一个 workflow 从"感觉能跑通"到"真跑通了"通常要一两个小时，运气差直接一下午。6 个人，半年里每个人都搞个三四回吧——保守估计 540 小时，差不多 3 个人月就这么没了。血亏。手动整合 CLAUDE.md？试过。第一周大家还挺积极，第二周没人更新，第三周那个文档就过期了。手动维护的知识库必死，这是人性啊，不是意志力的问题。我当时已经想放弃治疗了。

直到有天我在 GitHub issue 评论区翻到一个叫 xskill 的东西。这玩意儿直接往 ~/.claude/skills/ 挂个 SKILL.md，Claude Code 原生加载，你的项目配置和全局 CLAUDE.md 都不受影响。不是搞什么子 agent，就是标准 skill 文件。装法也简单：pip install xskill，然后跑 xskill serve --server 把服务拉起来。客户端会自动收集运行轨迹，脱敏之后上传，再从服务端同步最新的 skill。

最骚的是它还有灰度发布——新 skill 不会直接替换旧的，而是 20% 的用户用新版，80% 用旧版，根据用户行为打分（叫什么 UX Score），新版胜出了才全量上线。我们跑了三周，小张居然没再问过 nginx 的问题了——当然也可能他只是终于记住了。实习生有次问我："为啥你们的 Claude Code 比我自己的好用？"我猜就是这玩意儿的功劳。不过它也不是完美：刚装的那几天啥产出都没有，冷启动阶段很尴尬；如果团队就两三个人，那 20% 的灰度样本根本不够看，没啥意义。

想试试的话：github.com/SkillNerds/xskill。反正装上就不用管了，随它去了。
