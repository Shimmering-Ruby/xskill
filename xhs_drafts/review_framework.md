# xskill 小红书推广笔记 · 审查框架

> 审查官定位：不是挑毛病，是帮内容获得传播力。
> 核心视角：一个在小红书刷信息流的开发者，划到这篇笔记时的第一反应。

---

## A. 流量维度

### A1. 标题点击率（CTR）预测

评判标准：
- 是否包含**数字**（"3个月"、"10倍"、"5步"等）？数字是信息流中最强的视觉锚点。
- 是否包含**反常识/冲突感**？如"XX其实是错的"、"别再XX了"。
- 是否击中**痛点词**？开发者群体的痛点词库：效率、重复劳动、踩坑、同事不懂、团队协作、提效。
- 标题长度是否在 15-25 字之间（小红书最佳 CTR 区间）？
- 是否有**身份感召**？如"给技术 leader 的..."、"用 Claude Code 的人一定要知道..."。
- 在信息流中与生活/美妆/旅行类笔记混排时，是否仍然能抓住技术用户的眼球？

评分：1-10 分

### A2. 完读率预测

评判标准：
- **开头 hook**（前 3 行）：是否在 1.5 秒内让人决定继续读？是场景还原/痛点共鸣/反直觉陈述？
- **中段节奏**：是否有"段落间 hook"（每段结尾引出下一段的悬念/好奇心）？有没有连续 3 行以上的纯说明/纯技术描述（断崖式流失风险）？
- **信息密度曲线**：是否前密后疏（读者在中段因"觉得已经懂了"而离开）？理想的密度曲线是**W 型**——高开、中段小低谷但用案例/段子拉回、结尾再给一个"没想到"。
- **视觉排版**：是否善用 emoji 分隔符、加粗、短段落？大段落（>5 行）数量？技术类笔记中纯文字墙是完读率杀手。
- **全文字数**：小红书技术干货类最佳完读区间为 600-1200 字。超过 1500 字需要极强的叙事能力。

评分：1-10 分

### A3. 互动率预测

评判标准：
- **评论触发点**：是否有"你觉得呢？"、"你们团队是怎么解决的？"等显性邀请？是否有隐性争议点（让人忍不住评论纠正/补充/站队）？
- **收藏动机**：是否提供了"以后用得上"的信息（步骤、命令、工具链接）？是否像一个 cheatsheet/备忘录？
- **转发动机**：读者转发的心理预期是什么——"炫耀型"（"看我多懂"）、"利他型"（"同事应该知道这个"）、"讨论型"（"你怎么看"）？
- **评论区预埋**：作者是否有准备好的第一条评论（补充信息/自问自答/引导讨论）？评论区策略是否清晰？

评分：1-10 分

### A4. 算法友好度

评判标准：
- **标签策略**：是否同时覆盖大流量标签（#AI #程序员 #效率工具）和精准标签（#CodingAgent #ClaudeCode #技术分享）？标签数量是否在 5-10 个之间？
- **话题借势**：是否挂靠了近期热点话题？（如 AI agent 热潮、Claude Code 讨论热度）
- **推荐池升级信号**：首发互动数据（2h 内点赞/收藏/评论比）是否有利于进入二级推荐池？内容是否有"让平台想推"的特征（教育价值高、互动率高、不像广告）？
- **合规红线**：是否有明显的导流行为（外链、二维码暗示）？是否有夸大宣传？

评分：1-10 分

### A5. SEO/搜索发现

评判标准：
- **搜索词覆盖**：用户可能搜索的关键词有哪些？列出 Top 10 预测搜索词并检查笔记是否自然覆盖。
- 高频搜索词预测：`coding agent 效率`、`Claude Code 技巧`、`AI 编程工具`、`团队 agent`、`skill 管理`、`agent 自动化`、`coding agent 推荐`、`程序员提效`、`AI 辅助编程`、`开发工具推荐`
- 笔记正文/标题是否自然包含了以上词汇（非堆砌）？
- **长尾搜索**：是否有被"how-to"类搜索（"怎么让 Claude Code 更好用"）命中的可能？

评分：1-10 分

## B. 用户心理维度

### B1. 收获感

评判标准：
- 读完后，读者能复述出几个新知识点？（理想值：2-3 个）
- 信息是否有**可操作性**？读者是否知道"看完我该做什么"？
- 是否有"密度感"——让人觉得这篇信息量很大、值得收藏？
- 是否避免了"读完觉得有道理但什么也记不住"的空洞感？

评分：1-10 分

### B2. 认知冲击

评判标准：
- 是否打破了读者的某个**认知惯性**？（如"你以为 skill 是手动管理的"→"其实可以自进化"）
- 是否有"哦原来如此"时刻？这个时刻出现在笔记的哪个位置？（理想位置：前 1/3）
- 冲击是否可信？如果读者的第一反应是"吹的吧"，那就失败了。
- 是否有**层次递进**的认知推进？（先破后立，先问题后方案）

评分：1-10 分

### B3. 参与欲望

评判标准：
- 读者是否会想在评论区表达自己的经验/观点？
- 是否制造了**安全的讨论空间**？（让人觉得"说错也没关系"而非"只有专家才配评论"）
- 是否有**未完成感**——故意留白，让读者想补充？
- 是否有**立场标签**——让读者想表态（同意/反对/补充）？

评分：1-10 分

### B4. 信任度

评判标准：
- 语言风格是否像**真人在聊天**？还是像新闻稿/PR 文？
- **AI 味检测**：以下特征出现任何一个即扣分：
  - "在当今 XX 时代..."开头
  - 连续使用排比/对仗句式
  - 使用"赋能"、"生态"、"闭环"、"抓手"等企业黑话
  - 每段都很工整、无口语化表达
  - 没有个人经历/案例支撑
  - 结尾用"让我们一起..."或"期待..."
- 是否有**具体的数字/案例/截图描述**来支撑观点？（"我们团队3个人用了2周" > "大幅提升效率"）
- 是否有**适当的不完美**？（承认局限、吐槽某个小问题——这反而增加可信度）

评分：1-10 分

### B5. 传播动机

评判标准：
- 读者转发的主要动机类型判断：
  - **炫耀型**（"我知道这个前沿的东西"）：需要内容足够 niche + 有逼格
  - **实用型**（"收藏备用/转发给同事"）：需要有明确的操作步骤或工具推荐
  - **社交型**（"你怎么看这个观点"）：需要有争议性或讨论空间
- 是否同时具备至少两种传播动机？
- 转发后，读者在社交场景中能否用一句话说清楚"我为什么转发了这个"？

评分：1-10 分

## C. 内容质量维度

### C1. 技术准确性

评判标准：
- 是否有事实性技术错误？（功能描述与实际不符、竞品对比有误）
- 是否有**夸大宣传**？（"彻底改变"、"颠覆性"等词汇需要谨慎使用）
- 对 xskill 的核心机制描述是否准确？重点检查：
  - 轨迹收集 → AtomTask 拆分 → TaskClusterAgent 关联 → SkillEditAgent 改进 → 灰度测试
  - 与 OpenSpace/Trace2Skill 的差异描述
  - UX Score 机制
  - 本地 harness 兼容性
- 是否混淆了"已实现"和"计划实现"的功能？

评分：1-10 分（技术错误一票否决，出现则直接 <=3 分）

### C2. 观点原创性

评判标准：
- 是否提出了**新的 insight**？还是在重复"AI 很厉害/agent 很有用"的老生常谈？
- 以下 insight 方向的覆盖度：
  - "skill 应该是自进化的，而不是手动维护的"
  - "团队知识沉淀的最短路径是无感化"
  - "agent 能力的关键不在模型，在 skill"
  - "灰度测试思维应该用在 skill 管理上"
- 观点是否有足够的**论证深度**？还是只是抛出结论？
- 是否在为"skill 自进化"这个认知赛道做品牌卡位？

评分：1-10 分

### C3. 行动指引

评判标准：
- 读者看完后，下一步行动是否清晰？
  - 最好：有明确的 1-2-3 步骤
  - 次好：知道去哪里了解更多（GitHub/官网）
  - 最差：读完不知道该干嘛
- CTA（Call to Action）是否自然？是否像广告？
- 是否有"试用门槛"说明？（让读者评估自己是否适合）

评分：1-10 分

### C4. 领域定位与品牌心智

评判标准：
- 这篇笔记是否在为 xskill 建立"skill 自进化"这个赛道的**品类认知**？
- 读者看完后，是否将"团队 agent skill 管理"与 xskill 建立了心理链接？
- 品牌植入是否自然？是"先有价值再提产品"还是"一上来就推产品"？
- 是否在建立**作者/团队的专家形象**？（这对后续内容的持续传播很重要）

评分：1-10 分
