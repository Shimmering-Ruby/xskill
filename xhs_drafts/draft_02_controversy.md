## 策略说明

用"你的 coding agent 根本不会学习"这个认知落差制造情绪冲击。大部分 Claude Code / Cursor 用户以为自己在"训练" agent，但其实每次对话都是从零开始——这个落差足以引发评论区的辩论。争议性标题拉高点击率，正文用技术论据把观点立住，评论区自然分化为"确实如此"和"不对，skill 系统可以解决"两派，形成流量飞轮。

## 标题

你的 Claude Code 根本不会学习

## 正文

我跟你说，用 Claude Code 半年，感觉它越来越顺手了——但别误会，不是它变牛了，是你变牛了。你学会了怎么哄它，怎么用 CLAUDE.md 给它指路，可 agent 本身呢？它啥都没记住。上周你手把手教它配 Nginx 反向代理的正确姿势，这周换个项目再问同样的问题，它又开始瞎猜。你的 coding agent，从你装上的第一天到现在，一点都没成长。

你可能会说，不是有 Memory 功能吗？有，但那是你手动存的，不是它自己学的。你不存，它就没有。这哪叫学习啊，顶多算个笔记本。就算你一个人能靠手写 CLAUDE.md 撑住，但你团队呢？同事 A 花一下午搞定的 workflow，同事 B 遇到同样的问题又得花一下午。每个人的 agent 都在重复犯同样的错，经验完全隔离，谁也不认识谁。

学术界早就在搞这事儿了，叫 trajectory-to-skill。港大的 OpenSpace、阿里的 Trace2Skill 都在搞。但都缺最关键的一环：谁来保证新学到的 skill 是对的？让 LLM 自己给自己打分？跟学生自己批改卷子有啥区别，纯属自嗨。

后来我在 GitHub 上翻到了 xskill（SkillNerds/xskill），它整了个灰度发布加用户行为打分的机制。三个 Agent 生成新 skill 后，不直接替换旧版本，而是 git commit 到 staging 分支——20% 用户用新版，80% 保留旧版。然后看行为信号：用新版的人是不是更少 undo？量化成 UX Score，不是 LLM 自吹自擂。只有胜出了才上线。

还有个挺聪明的设计：证据累积到 weightscore 总分大于等于 10 才触发 skill 更新。团队模式下，一台 server 带全队 client，A 踩过的坑自动变成 skill 推给 B，B 再也不用重复踩了。轨迹脱敏上传，支持 5 个 agent 生态。想用的话，pip install xskill 就行，就这么简单。

## 评论区预埋

**评论 1**（制造争论）：
"我知道肯定有人会说'CLAUDE.md 写好了就行了'。但你团队 10 个人，每人维护自己的 CLAUDE.md，三个月后这些文件有多少已经过时了？有多少从来没被分享过？手动维护的东西一定会腐烂。"

**评论 2**（引导认知转变）：
"评论区有人问'Claude Code 不是有 memory 吗'。有，但那是你存的，不是它学的。你不存它就没有。这不叫学习，叫笔记本。"

**评论 3**（抛出延伸话题）：
"其实更大的问题是：当 AI 编程工具越来越好用的时候，不同水平的开发者之间的差距会拉大还是缩小？如果 agent 不能自进化，差距只会更大——因为会 prompt 的人越来越高效，不会的人原地踏步。"
